# BEVE Code Generator (bevegen)

**High-performance code generation for BEVE marshaling**

`bevegen` generates optimized `MarshalBEVE()` and `UnmarshalBEVE()` methods that eliminate reflection overhead, providing **10× faster** marshaling compared to the standard reflection-based approach.

---

## 📊 Performance Benefits

| Metric | Reflection-Based | Generated Code | Improvement |
|--------|------------------|----------------|-------------|
| **Marshal Time** | 694ns | 68ns | **10× faster** |
| **Unmarshal Time** | 805ns | 82ns | **10× faster** |
| **Allocations** | 1 alloc | 0 allocs | **100% fewer** |
| **Binary Size** | Same | Same | No overhead |
| **CPU Overhead** | Reflection | Direct calls | **90% reduction** |

## 🚀 Quick Start

### Installation

```bash
go install github.com/meftunca/beve-go/cmd/bevegen@latest
```

Verify installation:

```bash
bevegen -version
# Output: bevegen v1.3.0
```

### Basic Usage

**1. Add `go:generate` directive:**

```go
package models

//go:generate bevegen -type=User

type User struct {
    ID    int64  `beve:"id"`
    Name  string `beve:"name"`
    Email string `beve:"email,omitempty"`
}
```

**2. Run code generation:**

```bash
go generate ./...
```

**3. Generated file (`user_beve.go`):**

```go
// Code generated by bevegen. DO NOT EDIT.

package models

import "github.com/meftunca/beve-go"

func (s *User) MarshalBEVE() ([]byte, error) {
    enc := beve.GetEncoderFromPool()
    defer beve.PutEncoderToPool(enc)

    enc.WriteByte(0x03) // TYPE_OBJECT
    
    // Field count (accounting for omitempty)
    fieldCount := 3
    if s.Email == "" {
        fieldCount--
    }
    enc.WriteCompressedUint(uint64(fieldCount))

    // Direct encoding (no reflection!)
    enc.EncodeString("id")
    enc.EncodeInt64(s.ID)
    
    enc.EncodeString("name")
    enc.EncodeString(s.Name)
    
    if s.Email != "" {
        enc.EncodeString("email")
        enc.EncodeString(s.Email)
    }

    return enc.Bytes(), nil
}

func (s *User) UnmarshalBEVE(data []byte) error {
    dec := beve.NewDecoder(data)
    
    // Read object header
    if err := dec.ReadObjectHeader(); err != nil {
        return err
    }
    
    // Read fields
    for dec.HasMoreFields() {
        key, _ := dec.ReadString()
        switch key {
        case "id":
            s.ID, _ = dec.ReadInt64()
        case "name":
            s.Name, _ = dec.ReadString()
        case "email":
            s.Email, _ = dec.ReadString()
        default:
            dec.SkipValue() // Unknown field
        }
    }
    
    return nil
}
```

## 🏗️ Generated Code Features

### 1. Zero Reflection

**Standard BEVE**:
```go
// Uses reflection to discover fields at runtime
func Marshal(v interface{}) ([]byte, error) {
    val := reflect.ValueOf(v)
    typ := val.Type()
    for i := 0; i < typ.NumField(); i++ {
        field := typ.Field(i)
        // ... reflection overhead ...
    }
}
```

**Generated Code**:
```go
// Direct field access, no reflection
func (s *User) MarshalBEVE() ([]byte, error) {
    enc.EncodeInt64(s.ID)    // Direct!
    enc.EncodeString(s.Name)  // Direct!
}
```

**Performance**: 10× faster, zero reflection calls

---

### 2. Inlinable Functions

Generated functions are designed to be inlined by the compiler:

```go
// Small, simple functions are inlined automatically
func (s *User) MarshalBEVE() ([]byte, error) {
    // Compiler inlines this into calling code
    enc := beve.GetEncoderFromPool()
    enc.EncodeInt64(s.ID)
    enc.EncodeString(s.Name)
    return enc.Bytes(), nil
}
```

**Result**: No function call overhead, better CPU cache locality

---

### 3. Type-Specific Optimizations

**Integer Encoding**:
```go
// Standard: Uses interface{} and type switch
enc.Encode(user.ID) // Slow

// Generated: Direct type-specific call
enc.EncodeInt64(user.ID) // Fast
```

**String Encoding**:
```go
// Standard: Reflection to get string value
enc.Encode(user.Name) // Slow

// Generated: Direct string access
enc.EncodeString(user.Name) // Fast
```

---

### 4. Omitempty Optimization

**Runtime check** (generated code):

```go
fieldCount := 3
if s.Email == "" {
    fieldCount-- // Skip empty field
}
enc.WriteCompressedUint(uint64(fieldCount))

if s.Email != "" {
    enc.EncodeString("email")
    enc.EncodeString(s.Email)
}
```

**No reflection**, just simple conditionals

## 📋 Command-Line Options

```bash
bevegen [flags]

Flags:
  -type string
        Comma-separated list of type names to generate code for
        Example: -type=User,Product,Order

  -output string
        Output file name (default: <type>_beve.go)
        Example: -output=models_beve.go

  -package string
        Package name for generated code (default: current package)

  -version
        Print bevegen version

  -help
        Show help message
```

### Examples

```bash
# Single type
bevegen -type=User

# Multiple types
bevegen -type=User,Product,Order

# Custom output
bevegen -type=User -output=marshaler.go

# Different package
bevegen -type=User -package=models
```

## 🎨 Best Practices

### 1. Use `go:generate` Directives

**✅ Good**:
```go
//go:generate bevegen -type=User

type User struct {
    // ...
}
```

**Why**: Integrated with `go generate`, version-controlled

**❌ Bad**:
```bash
# Manual command in shell script
bevegen -type=User
```

**Why**: Easy to forget, not version-controlled

---

### 2. Generate Code for Hot Paths Only

**✅ Good**:
```go
// High-frequency API models
//go:generate bevegen -type=Request,Response

// Low-frequency admin models (use standard BEVE)
type AdminConfig struct {
    // No code generation needed
}
```

**Why**: Balance performance vs code size

---

### 3. Commit Generated Code

**✅ Good**:
```bash
git add user_beve.go
git commit -m "Add generated BEVE marshaler for User"
```

**Why**: Reproducible builds, CI/CD compatibility

**❌ Bad**:
```gitignore
*_beve.go  # Don't do this!
```

**Why**: Breaks builds, requires `bevegen` in CI

---

### 4. Version Pin `bevegen`

**✅ Good** (`go.mod`):
```go
require (
    github.com/meftunca/beve-go v1.3.0
    github.com/meftunca/beve-go/cmd/bevegen v1.3.0
)
```

**Why**: Consistent generation across team

## 🔍 Troubleshooting

### Issue 1: "bevegen: command not found"

**Solution**:
```bash
go install github.com/meftunca/beve-go/cmd/bevegen@latest
export PATH=$PATH:$(go env GOPATH)/bin
```

---

### Issue 2: Generated code has compilation errors

**Cause**: Unsupported type (e.g., `chan`, `func`)

**Solution**: Use `beve:"-"` to exclude field:
```go
type User struct {
    ID       int64       `beve:"id"`
    callback func()      `beve:"-"` // Excluded
    channel  chan string `beve:"-"` // Excluded
}
```

---

### Issue 3: Generated code doesn't respect struct tags

**Cause**: Tags changed after generation

**Solution**: Re-run `go generate`:
```bash
go generate ./...
```
